# Soliss AI/RPA Factory · P0 explicado mediante historias de usuario

**Proponente:** Keedio  
**Cliente:** Soliss  
**Carácter:** material pedagógico de apoyo. Los ejemplos son ilustrativos y no amplían el alcance contractual.

## Historia 1 · Un siniestro entra en Soliss
UC2 + UC3: entrada → identidad P0 → Document Intelligence → datos gobernados → señales asistidas → profesional Soliss → evidence trail.

## Historia 2 · Un empleado consulta un procedimiento
UC1: consulta → identidad P0 → RAG autorizado → Model Gateway → respuesta contextual → escalado humano → observabilidad.

## Historia 3 · Una factura llega a Administración
UC2 + UC5: factura → extracción → permisos P0 → reglas/integraciones → caso normal/excepción → validación humana → auditoría.

## Idea clave
Las tres historias reutilizan identidad, datos gobernados, Model Gateway, servicios IA/RPA comunes, observabilidad, auditabilidad y patrones de human-in-the-loop. La lógica funcional y las reglas concretas pertenecen a los UC derivados.
